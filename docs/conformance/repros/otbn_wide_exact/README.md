# OTBN wide exact covergroup bins

This change represents unsigned packed exact values from 65 through 256 bits in coverpoints and static crosses. Each 64-bit word is matched against the complete sampled four-state vector; words of one value are ANDed, while alternate values are ORed. An unsized open bin array gets one counter and value-keyed name per distinct exact value, limited to 256 values. Known-width wide wildcard, range, transition, sized-array, ignore/illegal, composite fill, and `binsof intersect` forms fail compilation when they cannot be represented.

The focused strict 2017/2023 JSON and legacy regressions are `sv_covergroup_wide_exact_cross`, `sv_covergroup_wide_open_array_named_cross`, and `sv_covergroup_wide_reject_unsupported` (six cases per runner). They cover 128/160-bit exact values and high-bit aliases, X samples, static automatic and named crosses, 256-bit `'0`/`'1` open-array values, and each unsupported-form diagnostic. Both runners passed 6/6 on the final local build. Separate strict 2017/2023 tiny reducers passed for event-driven sampling and `illegal_bins = default` classification of a high-bit alias.

The selected copied-source OTBN compile in [`selected_compile_evidence.json`](selected_compile_evidence.json) returned 0 with **zero** of the previous 180 dropped-bin diagnostics and zero hard errors. Its log has six unrelated warnings; [`selected_compile.log`](selected_compile.log) preserves them. The evidence records the exact command, binary hashes, filelist/source hashes before and after compilation, pinned OpenTitan source revision, and the disposable source-copy path. The source copy changes two mnemonic/CSR bin-source macros to `localparam`, scalarizes flag selection before ten sample calls, and moves a tracer assignment below its packed-struct declaration. This is a diagnostic selected profile, not a pristine-source OTBN compile. No OTBN DV runtime or full corpus was run.

Boundaries: the 256-bit `'1` bin declaration works, but passing bare `'1` directly to `covergroup.sample()` was observed to sample value 1; the positive reducer assigns `'1` to a typed 256-bit variable before the call. Complex packed-struct bitwise coverpoints in the existing `sv_covergroup_packed_bitwise_shape_wide_unsupported` test still emit the prior `sorry:` diagnostics, and unpacked-array element select width is a separate pre-existing issue. This change does not claim support for those forms.
