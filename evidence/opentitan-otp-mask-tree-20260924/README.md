# OTP arbiter packed-tree RED

The pinned OpenTitan OTP smoke remains **0/1 released DV** on Icarus. It reaches `tb.dut.u_otp_arb` and reports the enabled `GrantKnown_A` assertion at 1,559,061 ps; the released run has no pass marker or meaningful checked traffic. The original smoke, compile command, binary hashes, and native DPI bundle are recorded in [the class-identity replay](../opentitan-otp-class-identity-20260924/README.md).

A copied VVP image with diagnostic prints only reports `req_i=00011111111111`, `ready_i=1`, `gnt_o=000xxxxxxxxxxx`, and the 31-bit `mask_tree` entirely Z at the failure. The pinned `hw/ip/prim/rtl/prim_arbiter_tree.sv` assigns `mask_tree[0]=0` and derives each child bit from earlier tree nodes; these selected continuous assignments form an acyclic dependency graph. The [emitted bytecode excerpt](otp_vvp_excerpt.txt) instead has a `.part` read of the full packed tree feeding that tree's `.concat8`. This locates the first wrong value before the later registered priority-mask and grant X values. The [diagnostic script](otp_arb_diagnose.py) and [output](otp_arb_diagnose.stdout) preserve the copied-image probe; they do not change the pinned application source or release checks.

The [paired strict 2017/2023 record](paired_red_result.json) uses the private PR #360 compiler/VVP. A legal three-bit disjoint packed-bit assignment tree compiles but produces `tree=zzz` and fails at runtime in both editions. Its scalar equivalent passes `100` in both editions. An overlapping continuous-driver control on one `logic` bit is rejected at elaboration in both editions. These are reducer results, not released DV passes.

The [pre-fix netlist stage probe](stage_probe_result.json) locates the first wrong representation in `collapse_partselect_pv_to_concat` (`netmisc.cc`), called from `PEIdent::elaborate_lnet_common_` (`elab_net.cc`) while selected-assignment RHS connections can still be incomplete. Its default netlist has `NetConcat8` driving the whole tree from a full-vector read and the reducer fails with `tree=zzz`. A diagnostic compile with the existing `-pDISABLE_CONCATZ_GENERATION=true` keeps the selected `NetPartSelect(PV)` drivers and runs to `tree=100`. Both probe outputs use the same pre-fix private compiler and VVP; this flag is only causal evidence, not a release option or the final fix. The existing post-elaboration `cprop.cc` selected-driver blend has a combinational-dependency guard, so the candidate is to remove the eager collapse and leave any safe blend until that stage. Paired legal, overlap, four-state, boundary, and true-cycle checks and the pinned OTP replay still determine whether the candidate is correct.
