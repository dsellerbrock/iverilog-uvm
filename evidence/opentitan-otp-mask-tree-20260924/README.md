# OTP arbiter packed-tree RED

The pinned OpenTitan OTP smoke remains **0/1 released DV** on Icarus while the final replay is running. The prior image reached `tb.dut.u_otp_arb` and reported the enabled `GrantKnown_A` assertion at 1,559,061 ps; that run had no pass marker or meaningful checked traffic. Its compile command, binary hashes, and native DPI bundle are recorded in [the class-identity replay](../opentitan-otp-class-identity-20260924/README.md).

A copied VVP image with diagnostic prints only reports `req_i=00011111111111`, `ready_i=1`, `gnt_o=000xxxxxxxxxxx`, and the 31-bit `mask_tree` entirely Z at the failure. The pinned `hw/ip/prim/rtl/prim_arbiter_tree.sv` assigns `mask_tree[0]=0` and derives each child bit from earlier tree nodes; these selected continuous assignments form an acyclic dependency graph. The [emitted bytecode excerpt](otp_vvp_excerpt.txt) instead has a `.part` read of the full packed tree feeding that tree's `.concat8`. This locates the first wrong value before the later registered priority-mask and grant X values. The [diagnostic script](otp_arb_diagnose.py) and [output](otp_arb_diagnose.stdout) preserve the copied-image probe; they do not change the pinned application source or release checks.

The [paired strict 2017/2023 record](paired_red_result.json) uses the private PR #360 compiler/VVP. A legal three-bit disjoint packed-bit assignment tree compiles but produces `tree=zzz` and fails at runtime in both editions. Its scalar equivalent passes `100` in both editions. An overlapping continuous-driver control on one `logic` bit is rejected at elaboration in both editions. These are reducer results, not released DV passes.

The [pre-fix netlist stage probe](stage_probe_result.json) locates the first wrong representation in `collapse_partselect_pv_to_concat` (`netmisc.cc`), called from `PEIdent::elaborate_lnet_common_` (`elab_net.cc`) while selected-assignment RHS connections can still be incomplete. Its default netlist has `NetConcat8` driving the whole tree from a full-vector read and the reducer fails with `tree=zzz`. A diagnostic compile with the existing `-pDISABLE_CONCATZ_GENERATION=true` keeps the selected `NetPartSelect(PV)` drivers and runs to `tree=100`. Both probe outputs use the same pre-fix private compiler and VVP; this flag is only causal evidence, not a release option or the final fix.

Removing the eager collapse alone passed the DAG reducer but exposed a strength regression. A fully covered independent weak-driver vector connected through `tran` resolved to `a=10 b=0` before the patch and `a=1x b=x` with the first candidate: the later `cprop.cc` blend used a nontransparent concat and upgraded the weak driver. The [strength differential](strength_differential_result.json) records a dedicated test passing with the installed pre-fix compiler, failing on the intermediate image, and passing on the corrected private compiler. The final `cprop.cc` blend uses transparent concat only for eligible fully covered vectors, preserving the previous `NetConcat8` strength behavior; the existing combinational-dependency guard keeps dependent drivers separate. [Corrected netlists](dag-corrected.netlist.txt) retain three selected drivers for the DAG and use [transparent concat](strength-corrected.netlist.txt) for the independent strength control.

The corrected private ivl SHA-256 `5164a40b3cd44b4fd58a42accf85c1433ecd42a3836f9eb304d6518ff8d31931` and unchanged private VVP `bbe72e9d` pass [six paired 2017/2023 focused cases](corrected_focus_result.json): legal DAG and weak/strong `tran` runtime, plus illegal overlap compile rejection. The DAG also covers reversed assignment order, a 31-bit boundary, X/Z propagation, and a real cycle without claiming a standard fixed point for cycles. Four neighboring runs pass, including initial port delivery. The candidate was independently reviewed without further source or test findings.

This is **0/1 released DV**, not a pass.
