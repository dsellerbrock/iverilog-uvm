# Caliptra CSRNG compile blocker closure

Pinned Caliptra v2.1.2 is at `49370266d12cb0c4a8f71b3a0ff7e54ba7d4866e` and the checkout remained clean. The absent include reported after package-order correction was **not an absent generated input**: `caliptra_reg_field_defines.svh` exists and is tracked at `src/integration/rtl/caliptra_reg/caliptra_reg_field_defines.svh` (SHA-256 `24717b633f63c0907d8fcc209621e45356fc1469436c19c82f862bfa173681c6`). Its `.rdl` source is tracked at `src/integration/rtl/caliptra_reg.rdl` (SHA-256 `e96df33b3ad7767271fc3f60f59de9532d9f135203bd1e2ae068c29a0a8145b4`). The pinned `tools/scripts/reg_doc_gen.py` emits `<input-RDL-stem>_field_defines.svh` into the matching generated RTL directory; `tools/scripts/reg_doc_gen.sh` includes `src/integration/rtl/caliptra_reg.rdl`. The generated header is checked into the release, so regeneration is not required for this compile.

The actual blocker was an omitted include search path in `src/csrng/config/csrng_tb.vf`: it has `+incdir+${CALIPTRA_ROOT}/src/integration/rtl` but not `+incdir+${CALIPTRA_ROOT}/src/integration/rtl/caliptra_reg`. `aes_clp_wrapper.sv:25` includes `caliptra_reg_field_defines.svh`; the compiler consequently could not find the already-present nested header. Other pinned test filelists explicitly add the `caliptra_reg` include directory.

The package-order issue is separate and legitimate under IEEE 1800-2017/2023 §26.3: the package must be compiled before an importing scope. The source `.vf` had the generic RAM module at line 28 and its imported package at line 44. This probe uses a disposable two-line filelist overlay that moves the package first and adds the missing include directory; it does not alter the pinned release or Icarus.

With both filelist-only corrections, Icarus 13.0 compiled the full selected `csrng_tb` filelist successfully in 0.27 seconds (exit 0, no stdout/stderr, 3.8 MiB VVP image). Exact invocation/environment/status is in `compile_command.json`; [`overlay.diff`](overlay.diff) and [`csrng_tb_package_first.vf`](csrng_tb_package_first.vf) show the overlay. The earlier intermediate missing-include diagnostic is retained as [`package_first_missing_incdir.stderr`](package_first_missing_incdir.stderr). The compile artifact SHA-256 is `c8c0535609bf822e6285ff9c65598a52d9c6511fa45e55d108008d1d84fa6596`.
