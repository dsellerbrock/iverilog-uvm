## Standards

IEEE 1800-2017 and 1800-2023 §7.5 permit dynamic arrays whose elements are dynamic arrays; newly allocated outer elements leave dynamic subarrays unsized. Both editions' §18.4 require a constrained `rand` dynamic-array size to be applied before element randomization, preserving existing elements; for *actual* class-handle elements, growth adds null handles and does not allocate class instances. The `foreach` size/iteration rule is §18.5.8.1 in 2017 and §18.5.7.1 in 2023: size constraints precede iterative element constraints. Sources: [2017 IEEE text](https://rfsoc.mit.edu/6S965/_static/F25/documentation/1800-2017.pdf), [2023 IEEE text](https://iccircle.com/static/upload/img20240319175450.pdf), [official IEEE 2023 record](https://standards.ieee.org/ieee/1800/7743/). The 2023 mirror explicitly shows `int arr2[][] = new[4]` with unsized inner arrays in §7.5.1 and the null-handle rule in §18.4. No clause beyond these was needed or inferred.

## First failing path and minimum scope

The normal constraint parser (`parse.y:4129`) accepts the outer `.size` expression. `constraint_class_container_size_ir_()` in `elaborate.cc:28436` lowers it to a size variable, and the pinned generated VVP contains property 61 `filter_cfg`, type `q8:rDo!D,D`, plus `.constraint "filter_cfg_size_c" "(eq s:61:v1 c:2:32)"`. The reducer's VVP has the same `rDo!D,D` type and `(eq s:0:v1 c:2:32:s)` IR. Thus parsing, elaboration and outer-size IR generation succeed. The **first failure in this reducer is runtime**: `z3_solve_pass_()` in `vvp/vvp_z3.cc:8970` groups every graph-solved `Do` or `Qo` property with class-handle collections and rejects any size change. `Do` also describes this nested dynamic-array property, so the message misidentifies the ADC element type. The later write-back loop (`:9105`) skips all `Do`/`Qo`; its `make_darray_for_type()` (`:4580`) has only integral element constructors and otherwise falls back to a 32-bit vector, so simply deleting the guard would corrupt the nested array. The root cause is missing typed object/container resize and write-back, with an overbroad diagnostic, not the PR337 guarded `dist` resolver.

The complete ADC behavior also needs the independently documented compiler gap: `elaborate.cc` drops `foreach (filter_cfg[channel]) filter_cfg[channel].size == ADC_CTRL_NUM_FILTERS` because the element is another dynamic array; the pinned VVP `filter_cfg_size_c` contains only the outer size. `constraint_class_container_size_ir_()` rejects indexed size paths. See `evidence/opentitan-adc-filter-debt-20260923/assessment.md`. Minimum complete fix: distinguish nested value-container elements from class handles using the declared type; construct a typed outer array while preserving retained inner arrays and modes; represent and solve each indexed inner `.size` after the outer dimension exists; resize those inner arrays to 8; then apply nested iterative/default constraints to real packed-struct elements. Graph solve must commit atomically and restore prior array shape/content/modes on failure. Actual class-handle arrays separately require the §18.4 retain/null semantics and must not be conflated with this ADC case.

Candidate ownership is `elaborate.cc` for indexed size/foreach IR, `vvp/vvp_z3.cc` for solve ordering and typed graph write-back, and possibly `vvp/vvp_darray.{h,cc}` / `vvp/class_type.cc` for container type construction and copy behavior. `parse.y` has no demonstrated defect. `ivtest/ivltests` should own permanent paired tests. The issue register records Claude ownership around `elaborate.cc` and `vvp/vvp_z3.cc`; coordinate those files before implementation. No compiler, tracked test, shared build, or OpenTitan source was changed here.

Acceptance: paired 2017/2023 positive tests for this outer-only reducer, full 2×8 packed-struct sizing/default fields, grow/shrink preserving retained nested values, and a real class-handle array that retains old handles and adds nulls; negative/rollback tests for impossible inner sizes or contradictory element constraints, disabled randomization and unconstrained size retaining the old shape; boundary tests for zero outer/inner sizes, preallocated wrong lengths, aliases/modes, and graph failure after a prospective resize. Keep the existing stable-handle regression `sv_randomize_global_handle_size_fail` passing until handle growth is implemented, then replace its expected failure with the required null-growth semantics.

## Coordinator standards verification

The coordinator checked the actual IEEE 1800-2017 and 1800-2023 PDFs at §§7.5 and 18.4. Both editions permit dynamic arrays with array-valued elements, default an uninitialized dynamic subarray to size zero, and require a constrained random array to resize before its elements are randomized. Both preserve retained elements and their `rand_mode`, activate new elements, and distinguish actual class-handle arrays (new handles are null; randomization does not construct objects). This confirms that the ADC packed-struct `[][]` case must not be rejected or labeled as a class-handle collection. The 2023 text additionally mentions size in solve-before and discarded soft constraints; those are separate from this reducer.
