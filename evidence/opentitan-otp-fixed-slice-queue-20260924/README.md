# OpenTitan OTP fixed-array slice to queue

Pinned Earlgrey-PROD-M6 (`a78922f14a8cc20c7ee569f322a04626f2ac6127`) assigns five slices of the fixed class property `otp_a` to a local queue at `otp_ctrl_scoreboard.sv:1373-1377`. The prior compiler rejected each as “Array cannot be indexed by a range.” Paired 2017/2023 REDs also reject direct fixed-array slices, while whole-array and pattern-to-queue controls pass. A packed scalar part-select assigned to a queue was incorrectly accepted.

The new blocking queue assignment path decodes a one-dimensional fixed unpacked slice, checks declared direction/bounds and element compatibility, snapshots a plain class-handle receiver once, and supplies the selected elements in declared order to the existing queue conversion. Dedicated tests verify ascending/descending and indexed slices, a single element, direct and class properties, copy independence, local/protected visibility against the declaring class, and scalar-source rejection. Independent review found and closed a false acceptance of external protected and derived-class access to base local properties in this new path. The same accesses in older scalar and whole-array paths remain a separate compiler defect. Object-backed elements and slices above 65,536 elements receive explicit `sorry` diagnostics until their value-copy/runtime lowering is established. The pinned sources and installed Caliptra compiler were not modified.

The final private ivl fingerprint, exact commands, log hashes, and per-target results are in `result.json`. Paired core controls pass 18/18, registered dedicated JSON passes 10/10, neighboring queue/array JSON passes 37/37, and negative tests pass 155/155. The pinned `otp_ctrl_sim` compile loses exactly the five target errors, falling from 15 to 10 explicit errors (exit 16 to 11); its remaining ten are strict mixed-driver diagnostics in `alert_esc_if.sv`. Pinned `chip_sim` still has 48 explicit errors and the `entropy_src_core.sv:3324` sensitivity assertion abort. Neither target reaches DV runtime. Caliptra's `-gcommercial-unsafe` nonstandard compatibility results remain separate.
