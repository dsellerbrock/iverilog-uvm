# OpenTitan alert clocking-output driver identity

Pinned `otp_ctrl_sim` contains continuous assignments to `alert_esc_if.alert_tx_final` and `alert_rx_final`, alongside clocking outputs that drive other members. The prior compiler treated a virtual write to hidden clocking-output storage as a possible write to every member of the interface. It falsely rejected the disjoint case, while accepting a static clocking-output write to the continuously driven member. The strict paired 2017/2023 RED matrix has 16 wrong verdicts among 36 cases (`red-matrix.json`).

`elaborate.cc` now resolves a generated clocking-output buffer or pending-mask write through its defining clocking declaration to the raw interface member. Unknown aliases and generated-looking names without a declaration remain conservative. A successful static output write is recorded for the late continuous-driver check; a declaration alone is not a write. Same-member overlaps reject in strict and explicit `-gcommercial-unsafe` modes. The final private image matches all 36 paired verdicts (`final-matrix.json`), passes the 20 paired JSON tests and seven legacy tests, and preserves 36 neighboring clocking and 155 negative results. The disjoint runtime fixture also checks an ordinary declared member whose name looks like generated storage.

The final-image full JSON suite was stopped in its long constraint section to leave CPU for the live Caliptra diagnostic. The earlier private image `d1897f32` completed 3,572/3,572 JSON tests; that count is not a full-suite result for the final `a0233c24` image.

The pinned OTP compile loses all ten `alert_esc_if.sv` mixed-driver diagnostics: zero explicit errors remain, but an unsupported fixed unpacked-array virtual-interface method input at `otp_ctrl_base_vseq.sv:411` still makes compile exit 1. `chip_sim` retains 48 explicit errors and the `entropy_src_core.sv:3324` sensitivity assertion abort. Neither target ran DV. The pinned checkout and installed compiler/VVP were unchanged. Caliptra's selected-52 `-gcommercial-unsafe` nonstandard compatibility campaign is separate from these strict OpenTitan checks; its six completed diagnostic cases are one pass and five `ERR_HWIF_IN` failures, with 46 unstarted and no full-52 result.

`result.json` records image hashes, exact pinned commands and log hashes. The paired fixtures are registered in `ivtest/regress-sv.list` and `ivtest/regress-vvp.list`.
