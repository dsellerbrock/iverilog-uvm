# DOE scan reset-window assessment

The unchanged pinned Caliptra v2.1.2 `smoke_test_doe_scan` is **not a strict pass**: the full L0 log has one `SVA ERROR: DOE STATUS valid bit not set after clear obf secrets cmd` after `cptra_rst_b` is asserted and then released (hard-reset release at `cycleCnt 243956`, reset release at `243966`). The later testcase pass banner and process exit 0 do not erase that error. `observed_failure_window.log.gz` preserves the relevant verbatim log segment.

The exact released assertion is `DOE_clear_obf_status_valid` in `src/integration/asserts/caliptra_top_sva.sv:190-198`: at `posedge rdc_clk_cg`, `disable iff (~DOE_PATH.rst_b)`, `clear_obf_secrets && rst_b |=> DOE_STATUS.VALID && DOE_STATUS.DEOBF_SECRETS_CLEARED`. The source comment explicitly calls out a reset/clear overlap corner where clear remains high and status needs an extra cycle. In scan mode, `soc_ifc_boot_fsm.sv:234` routes `cptra_rst_b` to the DOE noncore reset; `caliptra_top.sv:1009` and `doe_cbc.sv:235` complete that path. The RDC clock is gated by `rdc_clk_dis` during the reset window (`soc_ifc_boot_fsm.sv:94`, `clk_gate.sv:86,91`). The services BFM's cold-reset sequence drives the logged assertion/release. `doe_cbc.sv:213` makes clear from a DOE_CLEAR command or a debug/scan transition; the status fields are set by clear at `doe_cbc.sv:194,198` but reset to zero by their respective reset paths.

The prior diagnostic probe recorded an antecedent sample with `clear=1 rst_b=1 hard_rst_b=1`, followed by a consequent sample and settled value with `clear=0 rst_b=1 hard_rst_b=1 valid=0 deobf_cleared=0` (`../caliptra-l0-52-and-full-dv-gap-20260923/doe_scan_probe.baseline.result.json`). Its retained JSON lacks timestamps. A newly authorized, disposable passive monitor resolves that gap. `monitor.patch` adds reset-transition and RDC-edge displays beside the **unchanged** property and action in a disposable copy; the retained source remains SHA-256 `7e832e09d1b95785db47226cc3dfaf1064771c14e413e354e7f66fd69938cac6`. The original test program, `+CLP_REGRESSION` argument, and isolated Verilator 5.052 were kept. The instrumented simulation exits 0 in 116.893 s, prints one SVA error and one testcase pass banner; it is diagnostic, not an L0 qualification run (`trace_result.json`, compressed full `trace.log.gz`).

The decisive window (`trace_window.log`) shows RDC edges at `$time=24394650` and `24394750` sampling `rst_b=1 clear=1`; DOE reset then falls at `24394750` (`rst_b=0`, `hard_rst_b=0`, `clear=1`). Reset rises at `24396650` with `clear=0`. The next logged RDC edge is at `24397250` and samples `rst_b=1 clear=0 valid=0 cleared=0`. The SVA error is printed adjacent to that edge; action-region ordering means the log alone does not assign the error an exact timestamp, but it lies after release and before or at this first displayed edge. No post-release RDC edge sampled a fresh `clear=1` antecedent before the error. A pending attempt from before reset is therefore the one Verilator failed. The last pre-reset edge and reset fall share a printed time; the preceding edge at `24394650` independently established a live antecedent before reset.

IEEE 1800-2017/2023 §16.12 requires `disable iff` to abort an attempt if its condition becomes true at any time between start and end, including between assertion clock edges. The existing minimal midwindow reducer demonstrates that Verilator 5.050/5.052 incorrectly retains such a direct-implication obligation; the generated `|=>` state in the full compiled replay also retains a sampled antecedent bit (`generated_sva_excerpt.txt.gz`; prior detailed analysis in `docs/conformance/session_logs/2026-09-23_caliptra_doe_verilator_defuture_blocker.json`). The released trace now makes that defect the **direct cause** of this one SVA error: a reset-low interval should have aborted the pre-reset obligation, yet the compiled property checked it on resumed RDC clocking.

`doe_reset_causality.sv` is a cheap discriminating control with a gated assertion clock. In both `-g2017` and `-g2023` Icarus runs (`causality_results.json`), the pre-reset attempt is disabled (`pre=0`), the deliberately new post-reset attempt fails (`post=1`), and the pre-reset property without `disable iff` fails (`control=1`). DOE RTL correctly has status high while pre-reset clear is high; reset clears the fields, and no new clear is sampled on the first resumed RDC edge. The released assertion's one-cycle status latency comment does not explain this failure as a fresh post-reset check. The practical path to a genuine strict pass is a validated Verilator fix for direct `|=>` disable across asynchronous reset, followed by unchanged pinned DOE scan replay and zero-SVA-error gate. No application assertion suppression or test-selection change is warranted.
