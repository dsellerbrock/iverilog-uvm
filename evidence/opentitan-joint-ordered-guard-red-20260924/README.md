# Ordered conditional joint-distribution RED

The unregistered [paired fixture](sv_joint_ordered_guard_fiber.v) and its [2023 wrapper](sv_joint_ordered_guard_fiber_2023.v) compile with the installed Icarus in both IEEE 1800-2017 and 2023 modes. Both runtimes exit 1 at time zero with `a joint distribution has an unresolved random guard`, before any checked `PASSED` marker. Exact commands, tool and source hashes, image hashes, and verdicts are in [result.json](result.json); compile and runtime streams are retained here.

The fixture randomizes two coupled child objects. Each child has a 7:3 `gate` distribution, `solve gate before value`, and a conditional weighted `value` distribution. It checks active weights, all three values in the inactive ordinary fiber, forced active/inactive calls, selected child agreement, post-randomize callbacks, value rollback, and RNG rollback after a hard UNSAT inline call. The failure occurs on the first `randomize()`, so these downstream checks remain RED and are not counted as passing tests. The fixture is intentionally absent from the regression manifests until a sound implementation makes it GREEN.

The existing proven-guard subset passes its separate 22/22 focus, but the [pinned CSRNG replay](../opentitan-csrng-proven-guard-replay-20260923/result.json) and [pinned OTP overlay replay](../opentitan-otp-backdoor-path-overlay-20260924/README.md) both fail `cfg.randomize()` on the unresolved-guard diagnostic. OTP is 0/1 DV at time zero, with no pass marker or meaningful traffic. Its RAM-path fatal was eliminated by the separate named source overlay. No Caliptra selected-52 result follows from this reducer.

`vvp/vvp_z3.cc` currently rejects a joint `dist` guard that varies over the unpinned hard solver, even if an earlier `solve ... before` stage could resolve it. A global per-distribution proof is not sufficient for coupled weighted subjects: an earlier weighted draw can shrink a later subject's support, turning a post-draw failure into biased successful samples. The current multi-distribution path deliberately skips full Cartesian component enumeration. The pinned child constraints suggest a factorization after the guard is fixed, but that is not yet a proof for the complete hard constraint set. No VVP source, build, installed tool, pinned application source, or checker was changed; the loud unsupported result remains in place.
