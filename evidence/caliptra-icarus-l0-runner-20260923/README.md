# Pinned Caliptra L0 Icarus runner

`run.py` selects [52 distinct released test YAML basenames](selected_52.txt) from Caliptra v2.1.2 commit `49370266d12cb0c4a8f71b3a0ff7e54ba7d4866e`. The pinned L0 YAML contains 62 active entries; the established release selection excludes clock-gating, watchdog-reset, and DMA profiles matching `smoke_test_(clk_gating|cg_wdt|mbox_cg|kv_cg|doe_cg|dma|wdt_rst)`. It uses the existing non-VERILATOR `caliptra_top_tb` filelist with `RV_OPENSOURCE`, `CLP_ASSERT_ON`, and `-gassertions`. Before running, it requires clean Caliptra and Adams Bridge checkouts at their exact pins, and it checks those states again afterward. Outputs must be outside the pinned source tree.

The runner builds each case's firmware with the recorded RISC-V toolchain and pinned Makefile. A fresh isolated `smoke_test_veer` rebuild reproduced all four recorded readmemh hashes, so the runner checks those exact values for its first case. It requires all four images to exist and records each hash; the pinned Makefile ignores some objcopy failures, and the testbench silently skips a missing image. Each simulator runs in its firmware directory so the testbench reads its `program.hex`, `dccm.hex`, `iccm.hex`, and `mailbox.hex` normally. The simulator explicitly loads the pinned native ARM64 JTAG DPI bundle; the runner rejects missing-DPI-symbol and JTAG bind/server diagnostics even if VVP exits zero. `+CLP_BUS_LOGS` records actual retired instruction traces. A pass requires a zero exit, one `* TESTCASE PASSED`, no failure/error/assertion or missing-symbol/JTAG-server diagnostic, no compiler warning that a checker operand is read live instead of sampled in the Preponed region, positive `minstret` and `mcycle`, and at least one instruction in `exec.log`. Build, compile, and simulation logs and JSON results remain in the chosen new output directory. Timeouts terminate the whole command process group.

On macOS ARM64, the runner also builds the ECC and MLDSA generators from the pinned C sources and a local FIPS 203 ML-KEM helper into its output directory, checks them against pinned Adams Bridge KATs, and stages them with DOE/SHA scripts into each case. It creates local `python` and `python3.9` aliases for the pinned SV commands. SHA256/WNTZ and MLDSA source copies receive the narrow, hash-guarded environment repairs described in [native vector evidence](../caliptra-native-vectors-20260923/README.md); pinned source trees stay untouched. The runner records hashes of tools, libraries, scripts, built generators, and each staged copy in `compile.command.json`, `native_vectors/result.json`, and case `result.json`. A changed stage cannot pass. The native preparation requires `clang`, `make`, `xxd`, Homebrew `openssl@3`, `mbedtls@3`, and `python@3.12`; tested versions were OpenSSL 3.6.3, Mbed TLS 3.6.7, and Python 3.12.14. The reference ML-KEM model named by the pinned integration profile is absent from the released tree, so the checked OpenSSL implementation supplies its exact file protocol without weakening the testbench.

The runner CLI defaults to strict mode, but this campaign runs the selected Caliptra L0 cases with explicit `--commercial-unsafe` as its main compatibility lane. That option adds Icarus's `-gcommercial-unsafe`; results carry `qualification: nonstandard_compatibility` in command, case, and summary records. Strict mode remains a focused IEEE conformance guard for genuine mixed-driver overlaps through the [paired driver controls](../caliptra-interface-driver-reducer-20260923/README.md); its full-top 46-error compile is historical baseline evidence, not the path used to count the 52 compatibility cases. A top compile blocker produces a structured `BLOCKED` summary with zero runtime tests attempted. A pass marker or zero simulation exit never overrides the runner's zero-error and meaningful-firmware requirements.

Apply any named Caliptra or OpenTitan test-selected source patch only to a disposable copy, with that test's patch and options recorded as described in the [release overlay guide](../../docs/conformance/release_overlays/README.md). Keep both pinned checkouts unchanged. The copied-reset option below is a separate diagnostic profile and cannot silently become the main L0 profile.

`--case NAME` selects one of the released 52 by name (`--all` selects all 52; the two options are mutually exclusive). Each selected `smoke_test_hw_config` or `smoke_test_hmac_errortrigger` case gets its own disposable Caliptra source copy. The runner dry-runs and applies only that case's frozen [C11 inline](../../docs/conformance/release_overlays/caliptra/hw_config_inline_c11.patch) or [standard-header](../../docs/conformance/release_overlays/caliptra/hmac_errortrigger_stdlib.patch) patch with zero fuzz; every other case builds from the pristine pinned source. Case results record their source root and selected patch's pre/post hashes. The summary records all case roots, and the end-of-run check rejects changed patch targets, including a patch target belonging to another case. It also checks the original Caliptra and Adams Bridge pins before and after. Run `python3 evidence/caliptra-icarus-l0-runner-20260923/check_firmware_isolation.py` to verify the per-case roots against the pinned sources and frozen patch hashes. The [two selected firmware build checks](firmware_overlay_build_check.json) exit 0 and produce nonempty `program.hex` images; firmware builds establish **no Icarus L0 runtime pass**.

`--commercial-unsafe --reset-overlay` additionally prepares a [hash-guarded copy of the bundled Caliptra integration BFM](../caliptra-l0-timezero-reset-overlay-20260923/README.md) under `/tmp` and uses its substituted filelist. This resolves a standards-permitted time-zero reset race for diagnosis without changing the pinned checkout or removing any checker. Its results carry `qualification: diagnostic_reset_overlay`; they are neither pristine-release L0 passes nor IEEE conformance results.

`--commercial-unsafe --checker-source-overlay` applies the frozen [checker patch](../../docs/conformance/release_overlays/caliptra/l0_pure_checker_functions.patch) to a hash-guarded disposable copy of the pinned SVA file, then substitutes that copy in the compile profile. The patch removes only nine internal print calls from four KV/MLDSA functions; their Boolean checks and all outer assertion failure actions remain enabled. A genuine failure still prints its outer action, though the first-mismatch detail is lost. [Paired 2017/2023 controls](../caliptra-l0-checker-source-overlay-20260924/README.md) cover vacuity, true pass/fail, reset disablement, and a same-slot NBA. The runner records source, patch, and copy hashes and labels this profile `diagnostic_checker_source_overlay`. Combining both options is labeled `diagnostic_reset_checker_source_overlay`. These diagnostic outcomes are separate from the pristine unsafe compatibility denominator; neither patch is an IEEE conformance result.

`--commercial-unsafe --ephemeral-jtag-port` copies only the pinned top testbench, changes its sole `jtagdpi` `ListenPort` value from `63224` to `0`, and substitutes the hash-guarded copy in the filelist. Port 0 lets the native TCP server request an OS-selected ephemeral port, avoiding fixed-port collisions during diagnostic replays; its startup message still prints `0`, not the assigned port. The runner records original/copied top and input/output profile hashes and rechecks them after the run. JTAG bind/server errors fail the case even if VVP exits zero or prints `TESTCASE PASSED`. This explicit option labels results `diagnostic_ephemeral_jtag_port_overlay`, or appends `ephemeral_jtag_port` to a combined diagnostic overlay label. It does not modify the pinned checkout or relax any L0 check, and its results stay separate from the pristine unsafe and IEEE denominators. Run `python3 evidence/caliptra-icarus-l0-runner-20260923/check_ephemeral_jtag_port.py` for the focused copy and error-gate check.

The baseline top compile emitted 32 Preponed-region sampling warnings for the released `KV_MLKEM_CHECK0` concurrent assertion. The final shared build's exact strict top compile emits zero after the paired nested constant packed-select fix; it still rejects the 46 mixed-driver errors. The runner records any sampling warning and disqualifies a runtime even if it later prints a pass marker. Nested dynamic-index sampling remains an unqualified boundary.
Run `python3 evidence/caliptra-icarus-l0-runner-20260923/check_guard.py` from this checkout to check those warning and runtime-error guards against the recorded baseline.

On macOS ARM64, install the native vector build dependencies and regenerate the local JTAG DPI bundle from the clean pinned Caliptra checkout. The bundle is deliberately not committed; the runner builds native vectors and each firmware image in its isolated output directory:

```sh
brew install openssl@3 mbedtls@3 python@3.12
campaign_root=$PWD
export CALIPTRA_ROOT="$campaign_root/../caliptra-rtl"
(
  cd "$campaign_root/evidence/caliptra-jtagdpi-native-20260923"
  "$campaign_root/local-install/bin/iverilog-vpi" --name=jtagdpi \
    -I"$CALIPTRA_ROOT/src/integration/test_suites/libs/jtagdpi" \
    -I"$CALIPTRA_ROOT/src/integration/test_suites/libs/tcp_server" \
    "$CALIPTRA_ROOT/src/integration/test_suites/libs/jtagdpi/jtagdpi.c" \
    "$CALIPTRA_ROOT/src/integration/test_suites/libs/tcp_server/tcp_server.c"
)
```

The runner checks the bundle hash before compiling and checks the first firmware's four image hashes before simulating. The xPack prefix must be at `../evidence/caliptra-exact-riscv-toolchain-20260923/toolchain/bin/riscv-none-elf`. Use a fresh output directory for each invocation. The first unsafe case failed at VVP image loading on operand-count and `$fatal` diagnostics; after those Icarus fixes, a second run loaded the image but stopped on a null virtual-interface anyedge wait in the internal AXI read path. The child's interface handle was copied before its parent's initialization. Later runs with the interface-order fix and native vectors are [0/1 on the pinned testbench](../caliptra-icarus-l0-unsafe-first-native-20260923/summary.json) and [0/1 with a diagnostic reset-timing copy](../caliptra-icarus-l0-diagnostic-reset-first-20260923/summary.json). Neither retired a firmware instruction or passed an L0 test. The copied profile reached finite preloads, then stalled at time zero after 100 million scheduler events; [a paired reducer](../caliptra-aes-timezero-20260923/README.md) isolated an `always_comb` function-local sensitivity defect.

With the interval-aware sensitivity and Preponed fixes, the [pre-PIC pinned first case](../caliptra-icarus-l0-unsafe-final-first-20260924/summary.json) compiled with zero sampling warnings and advanced to 43.865 us with 621 instruction-trace entries. It was **0/1**: the TLU, `soc_ifc_reg` `ERR_HWIF_IN`, and Veer store-buffer assertions fired, VVP exited 1, no `TESTCASE PASSED` marker appeared, and 17,467 error diagnostics disqualified the run. The missing final CSR dump meant `retired_instructions` and `cycles` were recorded as zero; 621 was an execution-trace count. An earlier [copied-reset diagnostic](../caliptra-icarus-l0-diagnostic-aesfix-first-20260923/summary.json) reached the same time and failed separately.

After the PIC packed partial-driver repair and its null guard, the [exact first compatibility replay](../caliptra-icarus-l0-unsafe-pic-nullguard-first-20260924/smoke_test_veer/result.json) completed firmware and simulation with exit 0, one `TESTCASE PASSED` marker, zero fail markers, 633 retired instructions, 4,348 cycles, and 634 trace commits. It still **failed 0/1** with 51 unrun because 17,863 bad diagnostics violated the unchanged zero-error gate. The old 43.865 us terminal SOC/TLU/LSU fatal was absent. Repeated messages from checker functions with false antecedents are documented in [paired evidence](../caliptra-post-aes-sva-triage-20260923/README.md); all diagnostics remain disqualifying. No L0 pass is established, and the remaining 51 compatibility cases are unrun pending a checked first-case pass. The [strict null-guard top compile](../caliptra-icarus-l0-strict-pic-nullguard-20260924/summary.json) still exits 46 on genuine mixed drivers with zero sampling warnings; it remains conformance-guard evidence.
