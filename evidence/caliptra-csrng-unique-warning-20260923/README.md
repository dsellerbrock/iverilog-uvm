# CSRNG `unique case` warning classification

The 252 warnings in the selected CSRNG runtime are real no-match diagnostics from `unique case (addr_hit)` at pinned `src/csrng/rtl/csrng_reg_top.sv:2386`, scope `csrng_tb.dut.u_reg`. A disposable hierarchical monitor around the same pinned testbench saw the first warning at time 0 while reset was low and the register bus was still initializing: `reg_addr=xx`, `addr_hit=xxxxxx` (24-bit all-X), `reg_re=x`, `reg_we=x`, `addrmiss=x`. It then settled at time 0 to `reg_addr=00`, `addr_hit=000001`, `reg_re=0`, `reg_we=0`, `addrmiss=0`.

The repeated runtime warnings are primarily idle address X values: the testbench's read/write tasks set `haddr_i_tb='Z` after transfers. The monitor traced 104 such states, each with `reg_addr=zz`, `addr_hit=xxxxxx`, and `reg_re=0`, `reg_we=0`, `addrmiss=0`. In total it traced 105 X states including the initial startup state. All stable known selectors in the traced run were one-hot decodes (`000001`, `000020`, `000040`, `000800`, `001000`, `002000`); no stable all-zero or known-unmapped selector was traced. `addrmiss` is separately gated by `(reg_re || reg_we)`, but the combinational read mux's `unique case` is unconditional, so it diagnoses idle X selectors as well as the initial startup X.

A tiny paired reducer confirms the relevant Icarus behavior: selector `xx` causes one unique-case no-match warning; the same case with matching selector `01` produces none. That supports expected unique-case diagnostic behavior for the observed X value. It does not show a missed CSRNG functional checker: the original runtime had one pass marker, no fail marker, zero Got/Want mismatch messages, and all 36 expected GENBITS reads. The instrumented run retained the same 252 warning count and pass marker. Treat the warnings as real X-state diagnostics from startup/transient/idle bus conditions, not as 252 distinct functional errors or a stable missing register decode.

Commands and raw output are in `compile_command.json`, `monitor_command.json`, `pair_command.json`, `monitor.stdout`, and `pair.stdout`; `summary.json` carries hashes, counts and source fingerprints.
