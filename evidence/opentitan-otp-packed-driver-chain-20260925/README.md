# OpenTitan OTP packed-driver chain

The pinned `otp_ctrl_smoke_vseq` failed `GrantKnown_A` with known requests and ready because the arbiter's packed `mask_tree` started at Z. A strict three-bit disjoint driver chain reproduced Z in both IEEE 1800-2017 and 2023 modes. `elab_net.cc` collapsed the selected drivers before their right-hand sides were elaborated, creating a self-referential concat whose ports never all delivered. The fix defers that collapse to `cprop.cc`, where the existing dependency walk can retain the original part drivers. The paired chain now settles and responds to input changes; the existing paired overlapping-variable cases still reject. The variable chain emits a “treated as wire” compile-progress warning, so its clean IEEE qualification remains open.

The first full JSON run caught a separate effect of retaining the part drivers: `br_gh1248` lost its SDF interconnect path through a packed resolver. A scalar, same-bit VPI path now finds it only when deferred links prove that bit has one structural driver. The [positive SDF output](sdf_exact.stdout.log) includes the 10 ps delay. [Wrong-bit](sdf_wrong_bit.v) and [competing same-bit](sdf_same_bit_competing.v) paths reject, while a [six-driver resolver](sdf_many_drivers.v) retains its delayed output. A [permanent SDF guard](../../ivtest/ivltests/sdf_singleton_guard.v) also rejects out-of-range source and destination port indices; its [runtime output](sdf_guard.stdout.log) shows all four rejected paths and an on-time signal change. No VVP concat startup rule changed.

The final private tool compiles and completes the exact pinned OTP smoke with all original assertions and native DPI loaded. It reaches `TEST PASSED CHECKS` with zero UVM errors. **Qualified released OTP DV remains 0/1:** [the compile log](otp_exact_compile.stderr.log) warns that `dai_wr_legal_addr_c` is ignored, and the [verbose replay](otp_exact_smoke_high_excerpt.log) selects DAI addresses outside the intended partitions. Six covergroup bins are also dropped. The hash-checked RAM-path overlay is the pre-existing disposable release compatibility input; the pinned OpenTitan checkout is unchanged. The checked-in stdout logs only have trailing whitespace trimmed.
