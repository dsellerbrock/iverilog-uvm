# CSRNG cfg joint `dist` triage

Pinned smoke evidence is from the unchanged released CSRNG overlay described in `pinned-cfg-result.json`. The exact VVP command and image hashes are recorded there; the re-run with `IVL_Z3_SOLVE_TRACE=1` is in `pinned-cfg-trace.pty.log.gz` (raw bytes compressed).

The failing invocation performs two `csrng_env_cfg` solves. The preliminary solve reports `vars=57 soft=8 dist=28` and succeeds. The dynamic solve (`dyn=1`) fails before a solve result with `joint dist requires an unconditional hard distribution with state-only weights and ground items`, surfaced as `cfg.randomize()` fatal at `dv_base_test.sv:41` at time zero.

The first `dist` constraint in the pinned `csrng_env_cfg` source is `otp_en_cs_sw_app_read_c`; it expands `DV_MUBI8_DIST` from `cip_macros.svh`. `_DV_MUBI_DIST` expresses its distribution in `if (TRUE_ > FALSE_) { VAR_ dist ... } else { VAR_ dist ... }`, i.e. a compile-time guarded hard distribution. The other `DV_LC_TX_DIST` site has the same macro form. This is the leading exact candidate because it appears first in the source-ordered distribution list; the current diagnostic does not identify a `DistSpec`, so this ordering-based identification is not instrumented proof. Nested `push_pull_agent_cfg` also contains four hard distributions guarded by `if (zero_delays)`, so dynamic conditional activation is another valid form in the same joint graph.

`csrng_macro_guard_red.sv` reproduces the pinned macro's constant-guard structure under paired `-g2017` and `-g2023`: nested objects with a shared field return the exact current joint-dist diagnostic. `csrng_macro_guard_single_control.sv` passes when the same guarded dist is randomized standalone. `joint_unconditional_control.sv` demonstrates nested joint unconditional dist remains supported; `joint_unsat_rollback_control.sv` verifies hard UNSAT returns failure without mutating prefilled values. `standalone_conditional_boundary.sv` covers a dynamic guarded dist without joint nested solving. The general dynamic-guard RED is in `joint_conditional_red.sv`.

All paired sources compiled and ran using `local-install/bin/iverilog -g2017` / `-g2023` and `local-install/bin/vvp`; compile logs are empty and run logs record results. No compiler, application, shared test-output, build, or install files were changed by this triage.

Standard basis: IEEE 1800-2017 §18.5.4 (`dist`) and conditional constraints in §18.5.7; IEEE 1800-2023 §18.5.3 (`dist`) and §18.5.7. The `dist` statements are legal hard constraints within conditional constraint blocks. The reduced failure is an Icarus joint-sampler eligibility restriction, not evidence that the pinned source is invalid. A sound fix belongs in `vvp/vvp_z3.cc`: resolve compile-time guards before rejecting exact joint distributions, then model variable guards per feasible assignment (or retain the explicit unsupported error if exact activation/weight composition cannot be proven). Do not treat an unresolved guard as inactive or silently fall back to soft/biased sampling.
